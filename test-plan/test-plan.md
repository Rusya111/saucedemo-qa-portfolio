# Тест-план: Swag Labs (saucedemo.com)

**ID документа:** TP-001  
**Название продукта:** Swag Labs (демо-интернет-магазин)  
**Версия документа:** 1.0  
**Дата создания:** 05.07.2026  
**Дата последнего обновления:** 05.07.2026

## 1. Введение и цель
**Цель тестирования:** Проверить корректность работы ключевых пользовательских сценариев (авторизация, каталог, корзина, оформление заказа) демонстрационного сайта Swag Labs. Убедиться, что интерфейс и логика приложения соответствуют ожиданиям, а также задокументировать найденные дефекты.

## 2. Область тестирования (Scope)

### 2.1. Что тестируем
| Модуль | Что проверяем |
| :--- | :--- |
| **Логин** | Вход с валидными данными (`standard_user`). Вход с пустым логином/паролем. Вход с неверным паролем. Проверка блокировки (`locked_out_user`). Проверка специфичных пользователей (`problem_user`, `error_user`, `performance_glitch_user`, `visual_user`). |
| **Каталог** | Отображение 6 товаров. Сортировка (по имени, по цене). Добавление товара в корзину. Удаление товара из корзины. Проверка отображения картинок и текста. |
| **Корзина** | Переход в корзину. Отображение выбранных товаров с ценой. Удаление из корзины. Продолжение покупок. |
| **Оформление (Checkout)** | Заполнение полей (First Name, Last Name, Zip Code). Позитивный сценарий успешного оформления. Негативные сценарии (пустые поля, проверка ошибок). Проверка итоговой суммы (Item total, Tax, Total). Подтверждение заказа (Finish) и появление сообщения «Thank you». |
| **Выход (Logout)** | Выход из системы. Проверка завершения сессии. |

### 2.2. Что НЕ тестируем (Out of Scope)
| Модуль | Почему не тестируем |
| :--- | :--- |
| **Дизайн и верстка** | Это демо-сайт, проверка соответствия макетам не входит в задачи. Цвета, шрифты, отступы глубоко не анализируем. |
| **Адаптивность** | Сайт не имеет полноценной мобильной версии. |
| **Реальная оплата** | Платежный шлюз отсутствует, оплата не производится. |
| **Производительность и нагрузка** | Проверка скорости работы под нагрузкой не проводится (кроме фиксации явных аномалий у `performance_glitch_user`). |
| **Безопасность** | Проверка на уязвимости (SQL-инъекции, XSS, пентест) не проводится. |

## 3. Стратегия и виды тестирования
| Тип | Что проверяем |
| :--- | :--- |
| **Функциональное** | Все кнопки, поля и переходы работают согласно бизнес-логике (логин, корзина, оформление). |
| **UI (Визуальное)** | Элементы отображаются корректно (поля, кнопки, названия товаров), нет наложений, ошибки видны пользователю. |
| **Негативное** | Ввод невалидных данных (пустые поля, неверный пароль, спецсимволы в Zip-коде, несуществующие пользователи). |
| **Smoke** | Быстрая проверка работоспособности после "релиза": логин (`standard_user`) + покупка 1 товара. |
| **Кроссбраузерное** | Базовая проверка в Chrome и Opera GX. |

## 4. Инструменты
| Инструмент | Для чего используется |
| :--- | :--- |
| **Браузер Chrome / Opera GX** | Среда для ручного тестирования. |

## 5. Критерии входа (Entry Criteria)
- Сайт `saucedemo.com` доступен по сети.
- Известны тестовые учетные записи (логины и пароли для всех типов пользователей).
- Подготовлены чек-листы и тест-кейсы (основные сценарии).
- Настроено окружение (актуальные версии браузеров).

---

## 6. Критерии выхода (Exit Criteria)
1. Все тест-кейсы уровня **Blocker** и **Critical** выполнены со статусом `Pass` (или переведены в `Fail` с заведенным багом).
2. Позитивные сценарии (логин, добавление товара, оформление заказа) отработаны на 100%.
3. Отсутствуют открытые баги уровня **Blocker**.
4. Открытых багов уровня **Major** — не более 2-х (остальные задокументированы).
5. Подготовлен итоговый отчет о результатах тестирования.

---

## 7. Риски и их митигация
| Риск | Что делаем |
| :--- | :--- |
| **Сайт недоступен или падает** | Проверяем доступность перед началом. Если падает — фиксируем как дефект окружения (Block). |
| **Специфичное поведение тестовых пользователей** | `locked_out_user` блокируется специально — это ожидаемое поведение. Для `problem_user` и `error_user` визуальные и функциональные баги являются *ожидаемыми* для демо-сайта. Фиксируем их в баг-трекере, но не считаем блокерами для релиза (так как это симуляция). |
| **Недостаточно времени для проверки всех пользователей** | Приоритизируем: сначала `standard_user` (основной путь), затем `locked_out_user`, затем остальные. |
| **Найденный баг не воспроизводится** | Четко записываем шаги, делаем скриншоты, записываем видео (через DevTools), указываем версию ОС и браузера. |

---

## 8. Классификация дефектов (Severity)
| Уровень | Описание | Пример |
| :--- | :--- | :--- |
| **Blocker** | Блокирует работу системы, тестирование невозможно. | Не работает вход с валидными данными (`standard_user`). |
| **Critical** | Ломает основной функционал, нет обходного пути. | Отсутствует кнопка оформления заказа, корзина не открывается. |
| **Major** | Ломает часть функционала, есть обходной путь. | Неверный пересчет итоговой суммы, не работает сортировка. |
| **Minor** | Незначительная ошибка, не влияет на функционал. | Опечатка в тексте, смещение иконки на 2px, неверный цвет кнопки. |
| **Trivial** | Косметическая ошибка. | Ошибка в тексте подсказки, которая редко используется. |
